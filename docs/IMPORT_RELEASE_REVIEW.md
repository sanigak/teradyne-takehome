# Import independently reviewed benchmark results

`scripts/import_release_review.py` records an already completed, independently reviewed benchmark in local quality history. It makes no model calls and does not claim that `python -m app evaluate` ran. Use the finalized joined adjudication artifact after its independent verdicts are locked. Current `Settings` selects the generation/review model pair.

Run the helper with the adjudication file as its positional argument. By default it writes review files under `docs/evaluation-results/imported-release` and leaves the runtime database untouched. `--gold`, `--adversarial`, and `--output-dir` override the input/output paths. Inspect `python scripts/import_release_review.py --help` for the complete interface. Add `--persist` only when ready to append the validated reports to the configured `DATA_DIR`.

Validation requires exactly 45 unique frozen case IDs and questions, an exact 15-case match to the original adversarial questions, immutable raw-report hashes, matching locked independent verdicts, and the current models, effective options, embedding configuration, complete prompts/digests, and answer-pipeline version. All 45 answers must use one identical, SHA-pinned 24-source corpus snapshot: original hashes and attribution must match frozen source gold; metadata and chunk digests must validate; the enrichment profile must match the current prompts/options; every answer's source ID, chunk ID, text, locator, filename and attribution must match that snapshot exactly. Historical reports missing that configuration or corpus proof are rejected rather than silently treated as current. Failed semantic and operational verdicts remain failed and retain quality alerts.

The two imported reports cover **45 unique questions**, with **15 overlapping questions** reported again under `evaluation_adversarial.json` so new actual findings can supersede that suite's earlier findings. They are not 60 unique tests. Quality reports count failed case instances per dataset/suite, so the same failure can appear in both reports. Earlier report rows remain stored; an identical import is a no-op, and an existing report ID with different findings is rejected atomically.

Benchmark query IDs belong to isolated benchmark history. The release corpus clone retains the reviewed main source/chunk IDs and metadata, but this does not imply that its query IDs exist in main query history. The helper validates answer evidence against the complete source snapshot, then checks exact quotations and routing against those records. Only quality reports are imported. Sources, user answers, feedback, and outbox records are not copied or rewritten.

If all 45 current-profile answers actually completed and independently passed, explicit persistence also records a full-suite scheduling identity anchored to the raw benchmark's completion time. That prevents an immediate duplicate paid daily run without making an old benchmark appear newly executed. Any failed or incomplete answer prevents that scheduling marker. This scheduling record identifies an imported independent benchmark review, not a CLI evaluation run.

The original model-comparison reviews were locked before model identities were revealed. Subsequent selected-configuration regression review is independent, with cost, latency, and automatic verdicts hidden, but is not a new fully model-blind comparison or human ground truth.
