# Practice uploading two new documents

The Documents page offers exactly two downloadable Markdown files from `data/upload_samples/`. They describe **Juniper Harbor**, a fourth fictional engagement with facts absent from the 24-document starter corpus. The files remain outside automatic corpus ingestion and are never uploaded on startup.

1. Before uploading, ask: **“When and where is Juniper Harbor's sandbox review, and who coordinates it?”** The starter corpus cannot establish that appointment. Download `juniper_kickoff_brief.md` from its sample card and use the file picker to upload it. Wait for the successful indexing outcome. Ask again: the new source supports **October 8, 2026, 14:00 UTC, Juniper training room, coordinated by Avery Quinn**.
2. Ask: **“What is Juniper Harbor's process for a missing warranty-policy answer, including its owner and review cadence?”** The kickoff alone does not establish this process. Download `juniper_escalation_playbook.md` and drag it into the upload area. After indexing, ask again: record the original question and product family in the sandbox review queue, assign **Samira Vale**, and use the internal review cadence **16:00 UTC on Tuesdays and Thursdays**. The source explicitly distinguishes that cadence from a customer response guarantee.
3. Open **Developer tools**, select **Search only — candidate evidence**, and search either question without generating an answer. Inspect the returned filenames, authors, dates, derived metadata, and source locations. Use **Documents** to preview the full source and download its original. Search itself does not create a query-history entry or review item.
4. Upload either identical file again. It should report **unchanged**, retain the same active source version, and leave the document count unchanged. If the model or effective enrichment options changed, re-enrichment creates a new version even when the file bytes are identical.

Starting from the pristine seed corpus, successful uploads change the active count **24 → 25 → 26**. Use the current count as your baseline if other documents have already been uploaded. Uploads persist across navigation and restarts; there is no reset or automatic removal. Changing a file under the same filename creates a new version while keeping old citations and downloads available. A failed replacement retains the previous successful version.

All seven supported extensions may be uploaded, one file per request, up to **32 MiB** each. Legacy Office formats require the configured LibreOffice executable. No multipart dependency is required: the browser submits raw file bytes with the filename as a query parameter. The outbox remains a simulation.
